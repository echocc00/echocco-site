VidSlice

Material vector index for video pipelines

v0.7.10 Apache-2.0 github.com/echocc00/VidSlice ↗

Overview

VidSlice indexes third-party video material — photos, clips, B-roll — into a LanceDB vector store, signs every entry with Ed25519 for tamper detection, and serves results over HTTP. Built to plug into the OpenCut short-video pipeline (which is why the HTTP API matches OpenCut's material contract).

v0.5 read-compat / v0.6 write opt-in via --compat v0.5 flag. NDJSON progress events for streaming pipelines.

Pain → Solution → Impact

Why a separate indexing tool exists, and what it changes for teams handing off material between vendors and the OpenCut pipeline.

Pain

Material processing for video search is fragmented

Every team rolls its own frame extractor and embedding pipeline. Vendors cannot be trusted with raw production assets, yet indexing has to happen somewhere. Index formats drift across teams, so a clip indexed by group A rarely loads cleanly in group B's pipeline.

Solution

A standalone CLI that signs a standardized index

VidSlice is a single CLI: hand it raw materials, it walks the directory, extracts frames, computes embeddings, and writes a signed index that OpenCut consumes directly. One tool, one output format, one signing scheme — every team's index looks the same on the wire.

Impact

Third parties index without seeing production secrets

Outsourced teams run VidSlice on the materials they're given; the signed index flows back to OpenCut without ever exposing production credentials, source repositories, or downstream services. Index format is consistent across vendors. The test suite reports 408 tests passing on every release.

How it works

Four CLI stages turn a directory of raw material into a signed vector index ready for OpenCut to ingest.

  1. 01

    Discover

    The CLI scans the materials directory, enumerating supported video and image files and recording their paths and hashes for downstream stages.

  2. →
  3. 02

    Extract

    Frames are pulled from each video and structured metadata (codec, duration, dimensions, source hash) is captured alongside them.

  4. →
  5. 03

    Embed

    A model computes per-frame vectors representing the searchable content; vectors and their metadata are written into the LanceDB store.

  6. →
  7. 04

    Sign

    The output index is signed with Ed25519, producing the standardized artifact OpenCut consumes directly — tamper-evident, version-pinned, and ready for the HTTP API.
